# 재료명 정합성 감사 및 정리 보고서 (2026-07-03)

## 1) 작업 배경

재료 데이터에서 공백 표기 불일치(예: `다진마늘` vs `다진 마늘`), 레시피 섹션 헤더 유입(`핵심재료2`), 단일 글자 쓰레기 항목(`칼`, `숯` 등)으로 인해 다음 문제가 발생하고 있었습니다.

- 동일 재료가 서로 다른 이름으로 중복 저장됨
- 상품 매핑 컬렉션(`coupang_products`, `kurly_products`) 문서 분산
- 레시피 내부 재료명이 비정규 형태로 누적

이번 작업의 목표는 **공백 표기를 1개 기준으로 통일**하고, **명확한 노이즈 항목 제거** 및 **재발 방지 로직 추가**입니다.

## 2) 정책 결정

- 공백 중복 문제는 **의미 단위가 드러나는 표기(공백 포함)**를 canonical로 채택
  - 예: `다진마늘` → `다진 마늘`
- 문제 2(브랜드/특정 상품명)는 이번 범위에서 보류
- 문제 3(레시피 섹션 헤더 유입)는 제거
- 문제 5(복합/대체 재료 표현)는 보류
- 문제 4(명확한 비재료 단일 글자)는 제거, 애매한 항목은 유지
  - 제거: `칼`, `숯`, `릭`, `랩`
  - 유지: `콘`, `윙`, `칩`

## 3) 코드 변경 사항

### A. `backend/services/recipe_service.py`

- `INGREDIENT_STANDARDIZATION_MAP` 확장/수정
  - 공백 비정규 → 공백 canonical 매핑 대폭 추가
  - 기존에 반대 방향(공백 → 무공백)으로 되어 있던 일부 매핑 교정
  - 다중 공백 변형 케이스(예: `꽃게가루육수`, `꽃게 가루육수`, `꽃게가루 육수`)를 단일 canonical로 통일
- 효과
  - 파싱 이후 표준화 단계에서 재료명이 자동 통일되어, 새 데이터부터 중복 유입이 크게 감소

### B. `backend/services/firebase_service.py`

- `add_scraping_ingredient`, `add_scraping_ingredients_batch` 개선
  - 공백 제거 + 소문자 기준 dedup key 도입
    - `무염버터`와 `무염 버터`를 동일 재료로 인식
  - 블록리스트 도입
    - 패턴 차단: `핵심재료`, `기본재료`, `선택재료`, `추가재료`, `마무리재료`, `부재료`, `토핑재료`, `양념재료`, `밑간재료`, `소스재료`
    - 정확 일치 차단: `칼`, `숯`, `릭`, `랩`
- 효과
  - scraping list에 잘못된 항목이 재유입되는 경로를 코드 레벨에서 차단

### C. `backend/scripts/cleanup_ingredients.py` 추가

- 1회성 Firestore 정리 스크립트 작성
  - `config/scraping_ingredients` 병합/삭제
  - `ingredient_unit_prices`, `coupang_products`, `kurly_products`의 비정규 문서 삭제
  - `recipes`의 `recipe.ingredients[].item` 명칭 일괄 치환 및 쓰레기 항목 제거

## 5) 문제 4 원인 분석

- 제거 대상 단일 글자(`칼`, `숯`, `릭`, `랩`)는 현재 활성 레시피에서 재현되지 않았습니다.
- 즉, 과거 파싱 산출물/삭제된 레시피/불완전 데이터 경로에서 scraping list에 잔존했을 가능성이 높습니다.
- 이번에 DB 정리 + 인입 차단 로직을 동시에 적용하여 재발 가능성을 낮췄습니다.
